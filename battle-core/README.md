Status 2026-09-26: **damage path with abilities, move effects, held items, and battler and arena tags verified against upstream** (singles). Upstream is `pagefaultgames/pokerogue` @ `8555c08`.

"Covered" means the C code hit nothing unported (see below). A few cases are left out because upstream itself throws on a random state no real battle reaches (Beat Up with inconsistent hit counters). A mutation check confirms the test notices when the code is wrong: changing any one of terrain power, the Stellar boost, Payback, Lash Out, Retaliate, weight power, Magnitude, Trump Card, friendship power, Freeze-Dry or Psyshock produces mismatches, and so does each of 19 deliberate item bugs (for example vitamins at +11%, Soul Dew's sign, Eviolite on a final evolution, Leek on any species, Knock Off counting untransferable items, Acrobatics counting virtual stacks, id -1 items ignored, and computing the damage tokens with the C library's `pow`, which alone gives 8 wrong damages in 30,000 cases). Of 43 deliberate tag bugs, 40 produce mismatches across the four seeds (screens on the wrong side, on crits or at x1, sports at x0.5, Lucky Chant on the attacker's side, Neutralizing Gas off or ignoring unsuppressable abilities, Charge at x1.5, Supreme Overlord at 20%, Focus Energy at 1 stage, Protosynthesis boosting every stat, Autotomize at 10 kg, Spit Up off, Smack Down off...). Some are caught by only a handful of cases, so they are thinly tested: a type boost matching the move's base type instead of its final type (2 cases), Spit Up with 0 stacks (2), Unburden (5), Substitute blocking contact (6), Disguise behind a Substitute (13) and Infiltrator going through screens (22). The 3 not caught: Neutralizing Gas keeping its user's other ability (needs passives), a sound move going through a Substitute (no case combined a sound move, a Substitute and an effect that depends on whether the move hits it), and Sturdy skipping its tag (a side effect nobody compares).

The differential test found real bugs, all fixed: Stellar Tera typing, Shedinja's forced Bug tera type, and charging moves (Fly, Dive) not counting as attacks for Wonder Guard. Until this revision it also skipped every move whose listed power is -1 (35 moves, among them Low Kick, Grass Knot, Heavy Slam, Flail, Gyro Ball, Electro Ball, Punishment, Seismic Toss and Super Fang), so their code was unchecked even though an earlier version of this README counted them as verified. They're in the test now and match.

What the test doesn't cover yet: doubles, fusions and passive abilities (the C dispatch reads a passive, but the producer turns passives off, so that path has never been compared). Tag code that is ported but not compared: status moves hitting a Substitute (the test only uses damaging moves), and Neutralizing Gas keeping its user's passive (needs passives). Side effects that belong to the turn engine (Volt Absorb healing, Sap Sipper's stat raise, Sturdy's tag, Disguise's form change) are recorded as *deferred*: the damage result is checked, the side effect isn't applied until the phase engine exists, and nothing compares the deferred list with upstream (so Sturdy skipping its tag when it already has one is ported but unchecked). Still uncovered: Analytic (needs the turn's move queue), Present (global RNG plus a heal side effect), Beat Up (needs the party), Parental Bond's damage boost, and Super Fang's later Multi Lens hits (they use the HP from the first hit, which upstream keeps between hits).

Two things upstream does that a reader might not expect, both kept: `getAttackDamage` doesn't cap damage at the target's HP, and with the enemy's damage tokens (up to 999 stacks of x1.05 in endless mode) it can exceed 2^63, so damage is a double in the C port too. And the JS `Math.pow` result depends on the engine: the reference here is Node 22 (V8 12.4), whose pow is fdlibm's; newer V8 versions switched to a correctly rounded pow, so upstream itself can deal 1 point more or less on a different browser.

## Design (the decisions that make 180k lines tractable)
1. **Data is generated, never hand-typed.** Upstream builds moves and abilities from ~430 attribute classes (`StatStageChangeAttr`, `StatMultiplierAbAttr`...). The dumper serialises every instance with its parameters. `gen/gen_tables.py` emits one C struct per class, a const table of instances, and an is-a bitmap for the class hierarchy. Upstream's `applyAbAttrs("X")` becomes "iterate attrs where `pr_attr_is(cls, PR_AC_X)`". Each class's C handler is written once; its 1,497 uses come free.
2. **Closures are tracked, not guessed.** Hand ports live in `src/closures_moves.c` and `src/closures_abilities.c`, each registered under the owner and source hash it was written against. A changed upstream closure therefore reads as unported instead of running stale logic. 735 upstream closures (move conditions, ability predicates) can't be dumped as data. They're listed in `gen/out/closures.txt` with a hash of their source. After an upstream bump, `tools/redump.sh` says exactly which ones changed. That's the answer to "upstream updates must be ported by hand": the tool tells you what to re-port.
3. **Unported logic is loud.** Every upstream `applyAbAttrs` site calls `pr_apply_ab_attrs`, which runs the C handler for each attribute class and reports any class without one. Move attribute sites call `pr_hook_move`. If a case touches anything unported, it's logged as *not covered*, never counted as a pass. The difftest prints the top missing classes, which is the porting to-do list, ranked by how often each class matters.
4. **State that isn't modelled yet has one entry point.** Wave data (`pr_wave_ability_applied`) is a single function in `src/hooks.c`. Modifiers and then tags went through the same kind of entry point until they were ported, and replacing it made every caller correct at once. The caller passes how much of that state upstream holds; with none, "absent" is exact, and with some, the query reports itself unported. Turn history (move history, attacks received, last turn order) is modelled by its length the same way: an empty history is exact, anything else is unported.
5. **Same arithmetic as JS.** IEEE doubles everywhere upstream uses JS numbers, `-ffp-contract=off`, the same operation order, and V8's own `Math.pow` instead of the C library's. Names follow upstream (`pr_get_effective_stat` = `Pokemon.getEffectiveStat`) so each function diffs against its TS original.
6. **No platform code.** Plain C99; builds on the PC for tests and with devkitARM for the 3DS (checked: compiles warning-free with `-march=armv6k -mfloat-abi=hard`). On ARM the logic is about 49 KB of code and the data about 380 KB of read-only tables.

## Layout
- `include/pr/` public headers (`rng.h`, `battle.h`)
- `src/` ported logic (`rng.c`, `hooks.c`, `pokemon.c`, `damage.c`, `move_attrs.c`, `ab_attrs.c` ability dispatch and handlers, `modifiers.c` held items and other modifiers, `tags.c` battler and arena tags, `js_math.c` V8's `Math.pow`, `closures.c` registry, `closures_moves.c` and `closures_abilities.c` hand-ported closures)
- `gen/dump-upstream.test.ts` dumper (runs in an upstream checkout), `gen/upstream/*.json` dump (not in git; `tools/redump.sh` recreates it), `gen/gen_tables.py` generator, `gen/out/` generated C (committed so the code builds without upstream; do not edit), `gen/check_closures.py` drift report
- `tests/difftest.producer.test.ts` upstream half of the differential test; `tests/difftest.c` C half; `tests/rng_*` RNG check
- `tools/setup-upstream.sh <dir>` clones and prepares upstream (no images or audio are fetched). `tools/difftest.sh <dir> [N] [seed]` runs a differential test. `tools/redump.sh <dir>` refreshes the data and reports closure drift.

Build: `make` (outputs to `build/`). `tools/closures.py` shows an owner's closures and fills registry hashes.

## Custom content (planned, not built)
Upstream ids are compiled into const tables. Custom species, moves, abilities and items will use a reserved id range (from 30000 up) and load from a small pack on the SD card at startup. They'll reuse the same attribute classes, so a custom move is data such as "StatStageChangeAttr {stats: [ATK], stages: 2}" plus, only if needed, a new C handler. Lookups already go through one function per table (`pr_pokemon_form`), which is where the custom registry plugs in.

## Known gaps in the tooling
- The dumper only reads enums from `src/enums/`; a few live elsewhere (e.g. `TerrainType` in `src/data/terrain.ts`), so those are written by hand for now (`include/pr/battle.h`).
- A closure's hash covers its own source and probed captures, not named helpers it calls (`anyTypeMoveConversionCondition`, `targetSleptOrComatoseCondition`). Check those by hand after an upstream bump.

## Not done (in rough order)
1. Weather and terrain lifecycles, tags being added, lapsing and removed over turns (only reading them is ported), status effects over turns, the other ~140 ability classes (switch-in, end-of-turn, contact effects...), and the held items whose effects happen outside the damage calculation (Leftovers, Focus Band, berries, Quick Claw, King's Rock, Shell Bell...).
2. Turn history (move history, attacks received this turn, turn order) so Rollout, Revenge, Stomping Tantrum, Fusion Flare and Analytic work past their first turn.
3. The turn engine: upstream's phase queue (`src/phases`, ~13.7k lines), turn order, switching, fainting, multi-target doubles. Deferred side effects get applied here.
4. Enemy AI, wave generation, trainers, rewards, biomes, mystery encounters, eggs, save format.
5. Hooking it to the renderer in `assets-pipeline/app-src`.

A real console run of this code hasn't happened. The float maths is only + - * / floor ceil, which ARM VFP rounds the same way, so I expect identical results, but that's inferred.
